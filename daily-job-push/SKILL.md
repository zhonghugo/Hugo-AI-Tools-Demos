# 每日岗位机会推送（Daily Job Push）

为一位求职者执行「解析画像 → 准备表格 → 生成关键词 → 搜索 → 筛选 → 去重 → 写入多维表格 → 回读验证 →（可选）推送摘要」的每日岗位机会闭环。

## 输入

- **必填**：求职画像（求职方向、城市、薪资区间、排除项、行业偏好等）
  - 用户已提供画像 → 直接解析
  - 未提供 → 用 `references/profile-template.md` 引导填写（含字段说明与完整示例画像）
- **可选**：目标多维表格 base_token / table_id；未提供时按 `references/table-schema.md` 自动建表
- **可选**：平台/方向限定（如“只看脉脉”“今天多推 AI 方向”）

## 工作流

### 1. 解析画像
明确：主攻方向、备选方向、城市、薪资区间、行业偏好、排除项（岗位类型/平台/地点）、每日目标条数。字段定义见 `references/profile-template.md`。

### 2. 准备多维表格
- 已有表格：先按 `references/table-schema.md` 导出全部已有记录，用于后续去重
- 无表格：按 `references/table-schema.md` 的字段规范建「岗位机会」表（飞书多维表格操作先读 lark-base skill）

### 3. 生成搜索关键词
把画像写成 profile.json 后运行 `scripts/build_keywords.py <profile.json>`，输出「城市 × 方向」关键词列表。画像未给方向时使用脚本内置默认方向集。**并行搜索每次不超过 3 个关键词**。

### 4. 搜索岗位
- 用 general_search 按关键词搜索；平台限定用 site: 语法（如 `site:maimai.cn 深圳 RPA`）
- 渠道：BOSS直聘、猎聘、智联招聘、前程无忧、脉脉、公司官网；**禁用平台见 `references/platform-rules.md`（拉勾已关停、鱼泡直聘不可用）**
- 脉脉可选 API 通道（配置 access_token 时）：`search_front/app/job_search` 端点拿岗位列表，详情页拼 `article/detail?efid=`；见 `references/maimai-api.md`
- **不再搜索纯"流程管理/流程经理/制度流程"关键词**（除非与 RPA/自动化实施相关）
- 结果落到搜索页/列表页时，从摘要或页面中提取岗位明细页链接（规则见 `references/platform-rules.md`）；**拿不到明细页链接的岗位不收录**

### 5. 筛选
逐条判定，全部满足才收录：
- 命中画像主攻或备选方向
- 地点符合（画像城市为主，周边需用户认可）
- 薪资符合画像区间，明显低于底线不收录
- 行业偏好命中（如餐饮/连锁/本地生活）优先级更高
- 不落入排除项（例如：以财务专业知识为核心的岗位、低质量平台、纯协调/汇报型管理岗、纯流程管理岗、猎头代招、英文岗、低于薪资底线）
- **有效性检查**：摘要/页面出现“职位已关闭”“已下架”“停止招聘”“已停招”“已下线”“已失效”等提示一律不收录；拿不准的链接先抓取页面验证仍在招聘

### 6. 去重
- 用 `scripts/dedup_keys.py <导出的ndjson> --keys-out keys.txt` 生成已有记录去重键（岗位名称+公司）
- 新搜到的岗位与已有键比对，同岗位同公司**不重复写入、不进入当日推送**（已存在的岗位不再推送）
- 历史标「不合适」的岗位同类型不收录；同公司不同岗位可重新评估

### 7. 写入表格
- 每条记录必填真实招聘链接，格式 `[查看岗位](url)`，url 必须为岗位明细页（`references/platform-rules.md`）
- 用 lark-cli `base +record-batch-create` 写入，每批 ≤200 条，串行执行
- 数量参考画像目标（默认 10-20 条/日）；搜索结果少时至少写入 3 条高匹配岗位，**宁缺毋滥，不写入明显不相关的岗位**

### 8. 回读验证
导出新写入记录核对：数量、字段完整性、招聘链接是否含明细页特征（`/job/`、`job_detail`、`/web/job/` 等）、发布日期是否当天。验证通过才结束。

### 9. 推送摘要（可选；定时任务必做）
通过 lark-cli im 向目标会话发送 Markdown 摘要：今日收录总数、方向分布、Top3 岗位（名称+公司+薪资+链接）、表格链接。**推送摘要只包含当日新收录的岗位，已存在于多维表格的岗位绝不进入推送**；当天无新增也要发送说明（已检查 XX 方向）。

### 10. 汇报
向用户汇报：方向分布、收录条数、最值得关注的 2-3 个岗位；提示到表格查看完整列表。引用搜索来源需带引用标签。

## 创建每日定时任务（可选）
用户要求“每天推送”时，按 doubao-cron-scheduler skill 规范创建 cron 任务（默认每日 10:00），query 中写入完整画像与筛选标准，触发时执行本工作流；摘要推送步骤必做。
